# Known limitations

- **Identity**: no Azentio Entra ID / OIDC and no `@azentio.com` domain enforcement; accounts are self-service email + password with emailed-code verification (needs `RESEND_API_KEY` + `MAIL_FROM`; until configured, staff verification is an operator step via `scripts/verify-email.mjs`). No password reset or MFA. Client invitation links are shown to the administrator and are not emailed automatically.
- **Not built**: attachments with private storage controls, hosted video/live streaming (recordings are https links; the portal gates who is given the link, but the target host must enforce confidentiality itself), email delivery of invitations and support replies (in-app only), embedding-based semantic clustering (moderator assist uses lexical TF-IDF similarity, so it misses paraphrases with no shared vocabulary), subscription digests, and the optional federated-learning track (P2; not claimed).
- **AIRA** selects the theme by keyword match. The optional LLM layer (`AIRA_LLM_API_KEY`) only rewrites the answer within that theme's approved evidence; it does not choose which evidence is permitted. Citation validation checks that cited ids were retrieved, not that every sentence is supported by them; the answer is labelled and carries its limitations. The prompt treats evidence as data, but prompt injection inside approved text is mitigated (tag stripping, output validation, moderation) rather than eliminated.
- **Reports** count distinct reporting users, not organisations, for the automatic hide threshold.
- **Theme matching** is keyword-based; moderators author themes and link approved publications manually.
- **Rate limiting** is a fixed-window counter in D1 keyed by client IP header; idempotency keys cover observation creation and the public forms.
- **Testing**: Vitest (56) and Playwright (50) pass locally; CI (`.github/workflows/ci.yml`) passed on earlier commits — see the Actions tab for the latest run. Visual QA is screenshot capture plus overflow/clipping assertions, not pixel-diff regression. `scripts/smoke-deployed.mjs` covers the deployed site; on 30 Oct 2026 every check (public, security, three-organisation loop, AIRA, improvements, entitlements, media gating, withdrawal within 60 s, and — added later — real invitation acceptance: email-bound, single-use, revocable) passed against production, most recently at commit 584cded, using a verified staff account.
- **Deployment / submission**: deployed on Vercel + Turso at https://azentio-collective.vercel.app (smoke test: `scripts/smoke-deployed.mjs`; client-side checks pass, staff flows need a staff login to run), no walkthrough video, and no multi-author commit history yet. A public site needs authentication enforced only on portal routes and APIs (or separate public and portal deployments).
- **Withdrawal** cannot recall content already read or copied and makes no model-untraining claim. Federated learning is out of scope.
- **Test data in production**: an earlier development test run accidentally wrote `local-demo-user` and synthetic-scenario rows into the production Turso database (they cannot be used to sign in). They are listed in the project history and should be removed by the owner before judging.
